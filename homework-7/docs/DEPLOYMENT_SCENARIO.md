# Сценарий внедрения клиентского модуля ИС «Умный кампус» на АРМ оператора проходной

| Параметр | Значение |
|---|---|
| Объект внедрения | АРМ оператора проходной (КПП корпуса А) |
| Устанавливаемый компонент | `Campus.Checkpoint.Client` 2.4.0 (клиентский модуль) + утилита `Campus.MealLedger` 1.0.0 |
| Задача | CAMPUS-210 |
| Ответственные | инженер внедрения (установка), сисадмин корпуса (сеть, учётные записи), старший смены охраны (приёмка) |

## 1. Требования к операционной среде

| Компонент | Требование | Как проверить |
|---|---|---|
| ОС | Windows 10 22H2 / Windows 11 23H2 и новее, x64 | `winver` |
| Процессор / ОЗУ / диск | 2 ядра, 8 ГБ ОЗУ, 2 ГБ свободно на `C:` | `systeminfo`, `Get-PSDrive C` |
| .NET | .NET 8 Desktop Runtime 8.0.x (x64), для утилиты достаточно .NET Runtime 8.0 | `dotnet --list-runtimes` |
| Время | синхронизация с NTP-сервером домена, расхождение не более 5 с | `w32tm /query /status` |
| Сеть, порт 443/TCP | исходящий HTTPS к `api.campus.local` (REST API) и к публичным источникам данных | `Test-NetConnection api.campus.local -Port 443` |
| Сеть, порт 4317/TCP | исходящий OTLP/gRPC к `otel.campus.local` (телеметрия, трассировки) | `Test-NetConnection otel.campus.local -Port 4317` |
| Сертификаты | корневой сертификат CA кампуса в хранилище «Доверенные корневые центры» | `certlm.msc` |
| Учётная запись | доменная учётная запись оператора без прав локального администратора | `whoami /groups` |
| Периферия | считыватель карт USB HID, принтер чеков/отчётов | «Диспетчер устройств» |

## 2. Чек-лист предпроектного аудита АРМ (Pre-deployment)

Чек-лист заполняется инженером внедрения **до** установки. Установка разрешена, только если все пункты с признаком «Блокирующий» отмечены как выполненные.

| № | Проверка | Ожидаемый результат | Блокирующий | Отметка |
|---|---|---|---|---|
| 1 | Версия и разрядность ОС | Windows 10 22H2+ / 11, x64 | да | ☐ |
| 2 | Последние обновления безопасности установлены | нет ожидающих обновлений | да | ☐ |
| 3 | Свободное место на диске `C:` | ≥ 2 ГБ | да | ☐ |
| 4 | Установлен .NET 8 Runtime x64 | строка `Microsoft.NETCore.App 8.0.x` | да | ☐ |
| 5 | Доступ к `api.campus.local:443` | `TcpTestSucceeded : True` | да | ☐ |
| 6 | Доступ к `otel.campus.local:4317` | `TcpTestSucceeded : True` | нет* | ☐ |
| 7 | Сертификат CA кампуса установлен, HTTPS открывается без предупреждений | статус 200 у `/health/ready` | да | ☐ |
| 8 | Время синхронизировано с NTP | расхождение ≤ 5 с | да | ☐ |
| 9 | Антивирус: каталог `C:\Program Files\SmartCampus` добавлен в исключения сканирования «на лету» | исключение есть | нет | ☐ |
| 10 | Учётная запись оператора создана, входит в группу `CAMPUS-Checkpoint-Operators` | группа есть в `whoami /groups` | да | ☐ |
| 11 | Считыватель карт определяется системой, тестовая карта читается | номер карты отображается | да | ☐ |
| 12 | Резервная копия старой версии клиента и его конфигурации сделана | архив в `D:\Backup\SmartCampus` | да | ☐ |
| 13 | Согласовано окно установки с начальником охраны (вне часа пик) | время записано в заявке | да | ☐ |

\* без порта 4317 программа работает, но телеметрия не отправляется — фиксируется замечание.

## 3. Пошаговый сценарий развертывания

| Шаг | Действие | Исполнитель | Время | Критерий успеха |
|---|---|---|---|---|
| 1 | Пройти чек-лист раздела 2, приложить скриншоты к заявке CAMPUS-210 | инженер | 15 мин | все блокирующие пункты выполнены |
| 2 | Сохранить резервную копию текущей версии и `appsettings.json` | инженер | 5 мин | архив создан |
| 3 | Установить .NET 8 Runtime (если отсутствует) из внутреннего репозитория ПО | сисадмин | 5 мин | п. 4 чек-листа выполнен |
| 4 | Распаковать дистрибутив в `C:\Program Files\SmartCampus\<версия>` | инженер | 3 мин | файлы на месте, хеш архива совпадает с опубликованным |
| 5 | Заполнить `appsettings.json` (адреса, пути) — **без секретов** | инженер | 5 мин | файл проходит проверку при запуске |
| 6 | Задать переменные окружения с ключами (раздел 4) | сисадмин | 5 мин | `CAMPUS_API_KEY` виден только учётной записи оператора |
| 7 | Создать ярлык на рабочем столе оператора, настроить автозапуск клиента | инженер | 3 мин | ярлык запускает программу |
| 8 | Смоук-тест: вход оператора, проход по тестовой карте, формирование тестовой ведомости `Campus.MealLedger --date <сегодня>` | инженер + оператор | 10 мин | проход зарегистрирован, CSV сформированы, код возврата 0 |
| 9 | Обучение оператора по `OPERATOR_MANUAL.md`, подпись в листе ознакомления | инженер | 20 мин | лист подписан |
| 10 | Закрытие заявки, запись в журнале внедрения | инженер | 5 мин | статус «Выполнено» |

**Откат.** Если смоук-тест (шаг 8) не пройден за 15 минут: удалить каталог новой версии, восстановить архив из шага 2, перезапустить клиент, проверить проход по тестовой карте. Заявка переводится в статус «Отклонено» с описанием причины.

## 4. Правила безопасной передачи ключей доступа

1. **В `appsettings.json` нет секретов.** В файле хранятся только адреса, пути, таймауты и справочные значения. Файл можно хранить в Git и копировать между АРМ.
2. **Ключи передаются через переменные окружения** уровня пользователя:
   ```powershell
   # выполняется сисадмином под учётной записью оператора
   [Environment]::SetEnvironmentVariable("CAMPUS_API_KEY", "<ключ>", "User")
   ```
   Переменные уровня «Система» (`Machine`) не используются — их видят все пользователи АРМ.
3. **Приоритет источников:** `appsettings.json` → переменные окружения `CAMPUS_*` → аргументы командной строки. Значение из окружения перекрывает файл, поэтому один и тот же файл конфигурации подходит для всех АРМ.
4. **Ключ не выводится в логи и на экран.** В журнале фиксируется только маска: `ключ API: ****a1b2`.
5. **Сам ключ передаётся** инженеру не по почте и не в мессенджере, а через менеджер паролей кампуса (общая папка «КПП»), срок жизни ключа — 90 дней.
6. **Запрещено:** передавать ключ аргументом командной строки (виден в списке процессов), записывать в ярлык, батник или `appsettings.json`, коммитить в Git. В репозитории `.gitignore` исключает `appsettings.*.local.json` и `*.env`.
7. **При компрометации** (ключ попал в лог, чат, репозиторий) ключ немедленно отзывается в консоли API, выпускается новый, инцидент регистрируется в Service Desk с приоритетом P2.

Переменные окружения, которые читает утилита `Campus.MealLedger`:

| Переменная | Назначение | Обязательна |
|---|---|---|
| `CAMPUS_API_KEY` | ключ доступа к API (передаётся заголовком `Authorization: Bearer`) | нет для публичного источника, да для боевого API |
| `CAMPUS_MEAL_SOURCE_URL` | адрес источника транзакций, перекрывает `SourceUrl` | нет |
| `CAMPUS_MEAL_OUTPUT_DIR` | каталог для CSV, перекрывает `OutputDirectory` | нет |
