# Комплект отчётных форм и журналов ИС «Умный кампус»

Общие требования ко всем формам:

- **Полнота данных** — каждая строка имеет уникальный идентификатор, обязательные поля не пустые; итоговые строки сверяются с детальными данными, при расхождении отчёт не формируется.
- **Защита от изменений** — журналы в БД только дополняются (INSERT), UPDATE/DELETE запрещены правами роли; к каждой выгрузке прилагается файл SHA-256; в PDF — нередактируемый слой и подпись ответственного.
- **Экспорт** — PDF (печать, архив) и Excel/CSV (анализ). CSV: разделитель `;`, UTF-8 с BOM, десятичная запятая.
- **Реквизиты шапки** — наименование формы, период, подразделение, кто и когда сформировал, номер страницы «Лист N из M».

## 1. Журнал регистрации проходов через турникеты

Назначение: учёт всех проходов через КПП, расследование инцидентов. Хранится 3 года.

| № | Поле | Тип | Обяз. | Описание / проверка |
|---|---|---|---|---|
| 1 | `pass_id` | UUID | да | уникальный идентификатор события |
| 2 | `event_time` | timestamptz (UTC) | да | время прохода; в отчёте — по МСК |
| 3 | `checkpoint` | string | да | код КПП / турникета (`A-T03`) |
| 4 | `direction` | enum | да | `IN` / `OUT` |
| 5 | `card_id` | string | да | номер карты |
| 6 | `person_name` | string | да | ФИО (в выгрузке для внешних — маскируется) |
| 7 | `category` | enum | да | студент / сотрудник / гость / подрядчик |
| 8 | `result` | enum | да | `ALLOWED` / `DENIED` |
| 9 | `deny_reason` | string | при `DENIED` | причина отказа |
| 10 | `operator` | string | да | учётная запись оператора смены |
| 11 | `trace_id` | string | да | идентификатор трассировки OpenTelemetry |

Требования: записи не изменяются и не удаляются; ошибочная запись исправляется **сторнирующей** с ссылкой на исходную; в отчёте контрольный итог «всего / разрешено / отказано». Экспорт: PDF за смену (подпись старшего смены), Excel за период.

## 2. Отчёт по загруженности аудиторий за месяц

Назначение: планирование расписания и ремонта аудиторного фонда.

| № | Поле | Тип | Обяз. | Описание / проверка |
|---|---|---|---|---|
| 1 | `room_id` | string | да | номер аудитории (`А-305`) |
| 2 | `building` | string | да | корпус |
| 3 | `capacity` | int | да | число мест, > 0 |
| 4 | `period` | ГГГГ-ММ | да | отчётный месяц |
| 5 | `planned_hours` | decimal | да | часы по расписанию |
| 6 | `actual_hours` | decimal | да | фактические часы (по датчикам присутствия / бронированиям) |
| 7 | `load_percent` | decimal | да | `actual_hours / доступный фонд часов × 100`, 0–100 |
| 8 | `avg_attendance` | decimal | да | средняя заполненность, % от `capacity` |
| 9 | `cancelled_classes` | int | да | отменённые занятия |
| 10 | `peak_day` | date | нет | день максимальной нагрузки |

Требования: отчёт строится по закрытому месяцу (после 1-го числа), повторное формирование даёт тот же результат; строка «Итого по корпусу» сверяется с суммой строк. Экспорт: Excel с диаграммой загрузки, PDF для учебного отдела.

## 3. Ведомость учёта питания в столовой

Назначение: учёт продаж и дотаций на питание для бухгалтерии. Формируется ежедневно утилитой `Campus.MealLedger`; хранится 5 лет.

### 3.1 Детальный журнал транзакций — `meal_transactions_ГГГГ-ММ-ДД.csv`

| № | Поле | Тип | Обяз. | Описание / проверка |
|---|---|---|---|---|
| 1 | ID транзакции | string | да | `MEAL-ГГГГММДД-NNNN`, уникален |
| 2 | Дата и время | datetime | да | `ДД.ММ.ГГГГ ЧЧ:ММ`, в пределах даты ведомости |
| 3 | Терминал | string | да | кассовый терминал `POS-01…03` |
| 4 | Карта | string | да | номер карты посетителя |
| 5 | Категория посетителя | enum | да | Льготник / Студент / Сотрудник |
| 6 | Категория питания | enum | да | Завтрак / Обед / Полдник / Ужин / Буфет |
| 7 | Сумма, руб. | decimal(2) | да | > 0 |
| 8 | Дотация, руб. | decimal(2) | да | 0 ≤ дотация ≤ сумма |
| 9 | К оплате, руб. | decimal(2) | да | = сумма − дотация |
| 10 | Источник | string | да | ссылка на исходную запись выгрузки |

### 3.2 Итоговая ведомость — `meal_ledger_ГГГГ-ММ-ДД.csv`

| № | Поле | Описание |
|---|---|---|
| 1 | Категория питания | группировочный признак |
| 2 | Транзакций | количество операций |
| 3 | Посетителей | число уникальных карт |
| 4 | Сумма, руб. | сумма продаж |
| 5 | Дотация, руб. | сумма дотаций льготникам |
| 6 | К оплате, руб. | оплачено посетителями |
| 7 | Средний чек, руб. | сумма / транзакций |
| — | Строка «ИТОГО» | суммы по столбцам 2, 4, 5, 6 |

Требования: итог ведомости обязан совпасть с суммой детального журнала (иначе код возврата 3, файл не выгружается); к двум CSV прилагается `meal_ledger_ГГГГ-ММ-ДД.sha256`; повторный запуск с той же датой даёт те же суммы. Экспорт: CSV/Excel для бухгалтерии, PDF ведомости за месяц с подписями заведующего производством и бухгалтера.
